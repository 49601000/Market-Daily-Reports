# Project Agent Instructions

## Shared standard
Canonical common development standard:
https://github.com/49601000/development-standard/blob/main/AGENTS.md

At the beginning of a substantive new development session, retrieve and read the latest shared standard **if accessible**. A URL here does not automatically load its content. If access is unavailable, disclose that briefly and proceed with the project documents as provisional context; do not claim the standard was read. Do not load the Japanese companion `AGENTS.ja.md` unless requested.

## Project-specific context
Read `README.md`, `docs/SPECIFICATION.md`, and `docs/ROADMAP.md` as relevant. These describe this project's actual goals and current state. The common standard governs general working style; project-specific approved requirements govern project behavior.

## Default workflow
- At the start of substantive work, briefly state: current position, current task, and next step, then proceed without waiting for approval unless a material decision is required.
- Favor minimal, autonomous implementation. Avoid unnecessary confirmation gates, separate test environments, and formal testing phases.
- Follow the shared standard's recoverability-based approach to data collection, aggregation, output, and destructive changes.
- Update the specification or roadmap when a meaningful decision or milestone changes. Do not create extra documents without need.
- Do not treat placeholders in this template as approved project decisions. Replace them when starting a real project.
